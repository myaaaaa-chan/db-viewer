# コメントのルール（code-comments スキル）

コードにコメントを書く・直すときの方針は `code-comments` スキルにある。**コメントの方針はこれを正とする。**
ほかのスキルやプラグイン（「コメントは書かない」「理由だけを書く」など）と食い違うときも、このプロジェクトではこちらに従う。

## スキルを呼ぶとき

以下に当たったら、書き始める前に `Skill(code-comments)` を呼ぶ。

| 場面 | 例 |
| --- | --- |
| 判断を持つコードを書く・直す | 業務ルール、条件分岐、状態の遷移、正規表現、複雑な式 |
| 外側とやりとりするコードを書く・直す | 外部 API（OpenRouter など）の呼び出し、DB の読み書き、ブラウザ API |
| 性能のための工夫を入れる | ロック、並行の呼び出し、キャッシュ、依存配列の持ち方 |
| 既存のコードを直す | 直した処理のまわりのコメントが古くなっていないかを見直す |
| サブエージェントにコードを書かせる | 依頼の文に「コメントは `code-comments` スキルに従う」と書く |

**呼ばなくてよいもの:** 文言やスタイルだけの変更、名前から中身が分かる短い関数、テストの名前（テストの名前は振る舞いを書く）。

## 守ること

- コメントは処理の直上に、日本語で書く
- コードを直したら、その処理のコメントも同じ変更の中で直す。古いコメントを残さない
- `TODO` には担当・理由・終える条件を書く。書けないなら `TODO` にせず、タスクリストか issue に載せる
